# Клиенты, люди и документы

Модель административного интерфейса:

```text
Клиент (аккаунт)
└── Люди
    ├── сам клиент (`self`)
    ├── супруг, ребёнок, родитель и другие родственники
    └── Документы каждого человека
```

## Маршруты

- `/customers` — список и CRUD клиентских аккаунтов;
- `/customers/documents` — каталог для выбора клиента и перехода к его людям
  и документам;
- `/customers/:customerId` — карточка клиента, CRUD людей и документов.

Клиент содержит телефон, необязательный email, имя, язык, валюту, часовой пояс
и статус. Пароля у customer нет: вход выполняется по SMS-коду. Клиента с
историей заказов удалить нельзя; такого клиента следует заблокировать, чтобы
сохранить историю.

При создании или сохранении клиента через административную форму имя и
фамилия обязательны. Аккаунт, автоматически созданный после SMS-входа, может
оставаться без заполненной фамилии до первого сохранения профиля.

Полный номер документа не возвращается API и показывается только в
маскированном виде. При редактировании пустое поле номера сохраняет прежний
зашифрованный номер, а введённое значение заменяет его.

Все операции используют сгенерированный OpenAPI-клиент и permissions
`users.read` / `users.write`.
