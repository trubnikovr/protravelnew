# Авторизация

Приложение запускается без обязательной авторизации и сразу открывает вкладку
`Home`. Авторизация показывается внутри вкладки `Profile`, только если у
пользователя ещё нет клиентской сессии.

При бронировании тура авторизация открывается модальным двухшаговым сценарием
поверх деталей тура: номер телефона, затем SMS-код. После успешной проверки
пользователь продолжает оформление того же тура без потери контекста.

## Маршруты

- `PhoneLogin` — ввод российского номера телефона;
- `VerifyCode` — ввод четырёхзначного кода из SMS-challenge.

`VerifyCode` получает `phone`, `verificationId`, `expiresIn` и необязательный
`developmentCode`. Последнее поле показывается только при работе backend с
mock SMS-адаптером.

## API

1. `POST /api/v1/auth/login` создаёт challenge на пять минут.
2. В mock-режиме ответ содержит код `4322`; реальная SMS пока не отправляется.
3. `POST /api/v1/auth/verify` возвращает access и refresh tokens.
4. Mock-код `4322`, возвращённый backend в `developmentCode`, автоматически
   подставляется в OTP-поле во время локальной разработки.
5. После успешной проверки вкладка автоматически переключается на содержимое
   профиля.

В dev-сборке поле телефона по умолчанию содержит `+7 999 123-45-67`, чтобы
mock-сценарий можно было пройти без ручного ввода. В release-сборке остаётся
только префикс `+7`.

OTP-поле использует `textContentType="oneTimeCode"` на iOS и
`autoComplete="sms-otp"` на Android. Поэтому настоящий код может быть
предложен системной клавиатурой из входящего SMS. Вставка строки из буфера
также поддерживается: поле извлекает первые четыре цифры.

Для iOS Simulator backend доступен по `localhost:3000`, для Android Emulator —
по `10.0.2.2:3000`. Перед production-сборкой адрес API должен быть вынесен в
конфигурацию окружения.

## Состояния

Оба экрана поддерживают отправку, loading и ошибку. Выход удаляет текущую
сессию и возвращает вкладку `Profile` на ввод номера, не переключая основную
вкладку приложения и не блокируя остальные разделы.

Сессия текущего mock-этапа хранится в памяти и сбрасывается после перезапуска
приложения. До production access/refresh tokens нужно перенести в защищённое
native-хранилище и подключить автоматическое обновление access token.
